Engineering and design handoff — 5 November 2026

Arca uses Apple's compiled String Catalogs and Foundation localization. SwiftUI receives the chosen locale and layout direction. There is no downloaded UI translation dictionary or replacement localization engine. See Apple's String Catalog guidance and SwiftUI accessibility fundamentals.

Adding or changing a string

  1. Edit the owning String Catalog in Xcode. Supply English, Arabic and Turkish values; add a translator comment when context is unclear.
  2. Resolve application copy through AppLanguage.localized or ArcaStrings.text. These are thin calls to String(localized:bundle:locale:) using the package's native language bundle.
  3. Use a complete sentence and format placeholders. Do not concatenate translated sentence fragments or add English suffixes to counts.
  4. For counts, add String Catalog plural variations. Arabic uses zero, one, two, few, many and other. Keep placeholder types consistent.
  5. Pass already translated copy to shared cards and inputs. Dynamic record content and custom field labels must remain verbatim.
  6. Format dates, amounts and numbers using Foundation format styles with the selected locale. Monetary values retain their stored currency; changing language does not convert currency.
let title = language.localized("Email")
let count = language.format("count.records", recordCount)
let date = savedAt.formatted(.dateTime.day().month().year().locale(language.locale))

Language and accessibility behavior

  • First launch follows the supported language preference reported by Foundation. An explicit in-app choice persists in UserDefaults.
  • Arabic sets SwiftUI's layoutDirection to rightToLeft. Directional navigation uses semantic SF Symbols such as arrow.forward.
  • Text uses semantic Dynamic Type styles through .arcaFont. Arabic uses bundled IBM Plex Sans Arabic with Font.custom(_:size:relativeTo:) and heavier faces for Bold Text; English and Turkish keep native system fonts. Keep SF Symbols, emoji and technical monospaced values native. Apply .arcaDefaultTypography() inside the locale environment for unstyled app text. Home and Insights grids become one column at accessibility sizes.
  • Important headings have header traits. Icon-only choices have spoken labels; selected items expose selected traits, so selection does not rely only on color.
  • Common clear, icon-choice and rating controls have at least 44-point targets. Native text inputs retain their normal editing behavior.
  • Reduce Motion disables SwiftUI animations at the root. Native controls retain their platform accessibility behavior.
  • Account inputs have email/password content types, Next/Done handling and a keyboard dismissal action. A non-consuming UIKit tap recognizer dismisses the keyboard outside editable controls, including sheets. Taps inside text inputs keep editing active.

How suggested collections are translated

The backend admin editor accepts optional localization JSON. Use a full valid translated schema, not a partial field patch. Keys and field type identifiers remain in the shared schema format; translate the collection name, field labels, options and subtitle. New migration data only translates untouched built-in starters and does not overwrite administrator customizations.

{
  "ar": {
    "subtitle": "وصف المجموعة",
    "schema": {
      "name": "معدات المنزل",
      "fields": [{"label": "اسم العنصر", "type": "short_text"}]
    }
  }
}

The AI prompt endpoint accepts language: en | ar | tr. It asks the external assistant for names and labels in that language while preserving the exact JSON keys and field types. Imported output still passes the shared strict schema validator.

Verification and screenshot reproduction

The capture source lives in ci/UXFlowCapture. It mounts production SwiftUI views with fictional data in a separate debug app, using an isolated local backend and a dedicated simulator. No personal workspace or iPhone is erased.

  1. Run the Laravel app against a disposable SQLite database, with migrations applied, on http://127.0.0.1:19274. Keep production credentials out of test commands.
  2. Prepare a standalone project, passing an output directory and an existing checkout of the pinned RevenueCat SDK:
python3 ci/UXFlowCapture/prepare.py /tmp/arca-ux-capture /path/to/purchases-ios-spm
xcodebuild -project /tmp/arca-ux-capture/ArcaUXFlows.xcodeproj \
  -scheme UXFlows -destination 'platform=iOS Simulator,id=YOUR_TEST_SIMULATOR' \
  CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=- \
  -parallel-testing-enabled NO -resultBundlePath /tmp/arca-ux.xcresult test
xcrun xcresulttool export attachments --path /tmp/arca-ux.xcresult \
  --output-path /tmp/arca-ux-images

Simulator ad-hoc signing is required for the test app's Keychain access. The capture app has a distinct bundle ID and uses separate temporary workspaces. Its test identity and recovery phrases are fictional.
