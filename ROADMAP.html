iOS release roadmap

Arca keeps personal records in collections you can design yourself. Save a warranty, find it again, and choose which Spaces stay on your phone.

Public release on hold. Records and keys survived a force-quit on a real iPhone, and encrypted record sync passed in both directions. The next release work is protecting local access and backups.

Finished

  • Deployed the Laravel backend. Arca runs over HTTPS at arca-api.on-forge.com on thekernel with its own PostgreSQL database. Live checks covered health, the public feed, denial of unauthorized admin access, and disposable account deletion. An isolated database restore recovered 16 tables.
  • Fixed relaunch data loss. The app uses a stable workspace and keeps its encryption keys and device identity in the iOS Keychain. Failed saves stay visible. A surviving legacy workspace can be migrated, but keys already lost by older builds cannot be reconstructed.
  • Connected iOS to Forge. Account sign-in, device enrollment, key recovery, encrypted collection and record changes, and saved sync progress use the live API. The initial sync also publishes existing local records whose old queue was empty.
  • Installed Arca 1.0 on an iPhone 12. The signed development app launched. In a separate test install, an abrupt process kill preserved the record ID, text, favorite flag and device identity. After relaunch, the app decrypted its test proof with the saved Space key and recovered the same master key.
  • Verified a sync round trip. A separate iPhone simulator recovered the phone’s test record through Forge, edited it, and published the edit. The physical iPhone received it after relaunch. The disposable account and test app were removed.
  • Removed medical demos from iOS starter menus. Onboarding and the template picker offer vehicles, warranties and home inventory. Examples are labeled fictional. Existing user collections keep their original identifiers.

Unfinished · in release order

  1. Authenticate the app lock. Replace the simulated unlock with system authentication. Verify on a real phone that success opens records and cancellation or failure keeps them hidden, including after relaunch.
  2. Protect exports and prove recovery. An empty password can currently produce plaintext when encryption was selected. Reject it, then restore an encrypted archive through Files on a clean install. Verify the recovered records and attachments and reject wrong passwords and damaged files.
  3. Implement sensitive fields and collections. The consent flow below is planned. Verify that local-only content never appears in a queued or uploaded payload while ordinary sibling fields continue syncing.
  4. Finish backend recovery and device access checks. Configure scheduled backups and restore one in isolation. Verify revoked devices lose access, including attempts to reuse a device identifier with an account token. Exercise offline edits, conflicting updates and remote deletion.
  5. Settle the paid launch scope. If selling Pro, remove the demo grant, configure RevenueCat and prove StoreKit purchase and restore, expiry and server entitlement updates. Otherwise keep paid actions out of the release.
  6. Finish or hide incomplete cloud features. Cloud attachment routes are disabled and the form adds a sample receipt. Public sharing is a preview. Verify real file uploads and snapshot publication/revocation before offering them. Validate iCloud Drive and Google Drive recovery before promising either.
  7. Prepare the iOS beta and App Store submission. Ship the icon, privacy policy and accurate privacy disclosures. Exercise account deletion through the app, VoiceOver, large text, Turkish and Arabic layouts. Run a signed TestFlight beta with fictional records and resolve its findings before public release.

Sensitive data · planned behavior

“Do you want to sync this sensitive field to the cloud?”

Name the field or whole collection and offer two choices: Keep on this device or Sync securely. Pause sync for the selected data as soon as it is marked sensitive.

Keep on this device
Allow local edits. Exclude the field’s name, defaults, values and attachments from outgoing schemas and records. For a local-only collection, exclude all rows and fields. Closing the prompt keeps the selection local.
Sync securely
Require the master password and verify it on the device before enabling encrypted sync. Require password setup first if needed. A wrong password or cancellation leaves sync off. The password never goes to Forge or into logs.
Apply the most restrictive choice
A local-only Space overrides every collection. A local-only collection overrides its fields. Other collections and ordinary sibling fields can still sync. Preserve local-only values when merging remote edits.
Handle data already synced
Remove stale queued payloads and rebuild eligible changes. Request deletion of remote copies and show it as pending until confirmed. Explain that an offline device may already hold a copy.
Prove the boundary
Inspect decoded test payloads after retries, offline edits and schema changes. Check automatic cloud backups, public snapshots, file uploads and derived labels. An explicit local export needs a separate choice and encryption.

Feature inventory

These are the current product surfaces. The finished list records which release checks have passed.

Spaces and collections
Choose local-only storage or Arca Sync, start from a template, or build a custom schema. Import and validate a pasted JSON schema.
Fields and forms
Eleven field types cover short and long text, number, currency, date, date and time, yes/no, single and multiple choice, rating and attachment. Set required fields, reorder or rename them, preview conversions and recover archived fields.
Records and search
Create, edit, duplicate, delete and favorite records. Browse recent items, search text, sort, and filter by favorites, options or attachments. Each Space has its own SQLite store and index.
Insights
View record counts, numeric and currency summaries, monthly spending, category distributions and upcoming warranty expirations.
Appearance and languages
Appearance controls and English, Turkish and Arabic support, including right-to-left layout. Some screens still use hard-coded English.
Backup, sharing and subscriptions
The archive engine can verify an export and restore it into a separate Space. Sharing includes a local identifier and a selected-field snapshot preview. Free and Pro tiers define device and storage limits. Release checks for these features are listed above.
