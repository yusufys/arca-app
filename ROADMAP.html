System architecture

Three views of the same product. Read each flow in numbered order.

Frontend

The iPhone is where records are written, searched and decrypted.

  1. SwiftUI screensOnboarding, Spaces, collection editor, records, insights and settings.
  2. App view modelArcaAppViewModel coordinates startup, saves, account recovery and sync while the app is active.
  3. Domain and storageArcaCore defines schemas and typed values. A catalog indexes Spaces. Each Space has a SQLite store for records, search and pending changes.
  4. Keys and servicesArcaCrypto protects sync payloads with Space keys. Keychain holds the local identity. Archive, billing and provider adapters serve separate user actions.

Device boundary. Saves and search work locally. Sync runs for eligible Spaces on user action and while the app is active. The remaining app-lock and archive defects are N1 and N2.

Backend

The Forge site runs the Laravel API on thekernel with a dedicated PostgreSQL database.

  1. HTTPS APIThe iOS adapter sends requests to arca-api.on-forge.com. Public routes include sign-in and the app feed.
  2. Account and device checksAuthenticated routes use an account bearer token. Sync checks the supplied device ID and enforces Space access and quotas.
  3. Sync serviceEnrollment and key discovery sit alongside Space registration, push and pull. Duplicate operation IDs are acknowledged without inserting another copy.
  4. PostgreSQLStores accounts, enrolled devices, wrapped key material and a per-Space operation log. Pulls return pages ordered by server cursor.

Service boundary. Forge needs routing metadata such as identifiers, revisions and cursors. Synced record and schema contents arrive encrypted. Admin access, account deletion and recovery are separate from public feed access. Production cloud attachment routes are disabled.

End to end

A warranty moves from phone A to phone B and back. The same path ran with a physical iPhone and an independent simulator.

  1. A saves offlineThe editor writes a record locally. For a synced Space, a pending change can be retried after reconnecting. A Local-Only Space stops here.
  2. A encrypts and pushesThe coordinator encrypts the record or schema with its Space key. Forge accepts the operation and returns its receipt. A records the acknowledgement.
  3. B recovers and pullsB signs in, enrolls and uses the recovery phrase locally to recover the master key. It unwraps Space keys, fetches changes, decrypts and applies them, and saves its cursor.
  4. B edits; A receivesB edits the warranty and pushes a new encrypted change. A pulls it on relaunch and displays the edited value.

Failure paths. A network error leaves pending work for retry. The cursor tracks applied changes. Concurrent edits can require conflict resolution. P1 adds local-only field filtering and guarded removal of prior server copies. The existing cloud recovery phrase and the proposed consent password serve different purposes.

Who can read a synced warranty?

The recovery phrase unlocks the wrapped account master key on the device. That master key unwraps the keys for each Space. Space keys encrypt and decrypt record and schema changes using authenticated encryption. Forge stores wrapped keys and encrypted changes so another enrolled client can recover them. The server still knows account, device and routing metadata. An authorized device must decrypt the record to display it, which is why real local authentication remains a release gate.

Collection design

Curate suggestions

An Arca administrator edits and publishes templates in the catalog editor. iOS refreshes at launch and when the gallery opens. Each selection creates an independent copy in the user's Space.

Describe a collection

Arca sends the user's description to Forge to prepare a prompt. The user can copy it or open ChatGPT, Claude or Gemini and paste it. Returning to Arca with the reply works offline.

Validate and save

The server and app use the same versioned rules. Arca extracts a single JSON object, checks field types, labels, titles and choices, and previews the result before saving it. Ambiguous replies and unsupported fields show an error.

Privacy contract

The candidate implements field and collection controls. Tests cover password checks, local-only exclusions and offline edits between two clients connected to a local Laravel server. Two independent clients also passed a scoped privacy purge and offline retry through the live Forge API. Repeat on the signed TestFlight build.

When a user marks data sensitive

Pause outgoing changes for that field or collection. Ask “Do you want to sync this to the cloud?” and name the affected item.

  • Keep on this device. Continue local edits. Exclude the field’s name, defaults, values and attachments. For a collection, exclude its schema and all rows.
  • Sync securely. Verify the master password on the device first. Require setup if none exists. Cancellation or a wrong password leaves sync off. Keep the password out of requests and logs.
  • Apply the strictest choice. A Local-Only Space overrides its collections. A local-only collection overrides its fields. Normal sibling fields in a synced collection may still sync.

When the choice changes

  • Already queued. Rebuild pending changes before sending. Exclude local-only content from schema updates, labels, automatic cloud backups, public snapshots and file uploads.
  • Already uploaded. Keep the local value. Request deletion of remote copies and show pending status until acknowledged. An offline device may still hold an earlier copy.
  • Acceptance scenario. On A, keep a serial number local and sync a warranty expiry. B receives only the expiry. Edit it on B and confirm A keeps its serial number. Repeat with the whole collection local, offline retries, and a separate explicitly encrypted local export.

Scope decisions

Proposed product calls for the iOS release owner. Each changes what the team must prove before submission.

Keep the first release narrow

  • Commit to local records, usable collections, dependable encrypted sync and clear data controls. Android is outside this launch.
  • Paid launch selected. Monthly, yearly and lifetime access use RevenueCat. Verify Apple products, SDK key, webhook deliveries and TestFlight purchase and restore.
  • Defer unfinished integrations unless proven in time. This includes cloud file uploads, external backup providers and public snapshot publication. Hide unavailable actions in the release build.

What changes the release call?

  • Private beta. Use fictional data and log exact builds. Assign a tester to each gate. Record pass, fail or deferred with the scope decision.
  • Public release. Require repeatable restore, authentic app unlock, privacy exclusion tests, revocation checks and a passing release candidate. Today’s passing sync test covers one round trip.
  • When evidence is missing. Keep the affected milestone open. A feature may be deferred only if its user-facing promise and entry points are removed from the candidate.
